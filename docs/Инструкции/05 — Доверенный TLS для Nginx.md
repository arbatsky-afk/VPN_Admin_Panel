# Доверенный TLS для Nginx

Инструкция включает доверенный HTTPS-сертификат для Nginx, установленного через
VPN Admin Panel.

## Перед началом

- Зарегистрируйте домен или используйте существующий.
- Создайте A-запись домена, указывающую на IPv4 сервера.
- Убедитесь, что DNS уже возвращает выбранный IP.
- Установите **Base + Security** и подготовьте доступ для **Deploy Nginx**.
- Порт 80 должен быть доступен из интернета для подтверждения домена.

## Выбор режима

После нажатия **Deploy Nginx** Panel проверяет актуальное состояние сервера и
показывает диалог желаемого конечного состояния:

- **Self-signed** — domain не требуется;
- **Let's Encrypt** — обязателен lowercase DNS domain без схемы и пути.

В журнале preflight показывается только краткое Inventory-состояние Nginx;
остальные установленные Components к этой операции не выводятся.

Для установленного Nginx действующие режим и domain уже выбраны в диалоге. Для
первой установки выбран **Self-signed**. Если состояние установленного Nginx
нельзя подтвердить, диалог не открывается и Deploy не начинается.
Точно распознанная прежняя self-signed установка без TLS state показывается как
**Self-signed** и переводится в текущий формат обычным повторным Deploy.

Выбор действует для текущего Deploy и постоянно локально не сохраняется. После
установки фактические режим и domain берутся из server-side Nginx state.

## Включение HTTPS

1. Выберите настроенный сервер.
2. Выполните **Check SSH**.
3. Включите **Editing**.
4. На вкладке **Deploy** нажмите **Nginx**, выберите **Let's Encrypt**, введите
   domain и подтвердите операцию.
5. Дождитесь успешного итогового сообщения.
6. Откройте domain по HTTPS и убедитесь, что браузер доверяет сертификату.

Отдельной кнопки для сертификата нет: доверенный TLS включается обычным Deploy
Nginx. После успешной установки продление выполняется автоматически и не
требует регулярного запуска Panel или повторного Deploy.

## Изменение режима

- **Self-signed → Let's Encrypt** — выберите Let's Encrypt и укажите domain.
- **Let's Encrypt → Self-signed** — выберите Self-signed; прежний domain будет
  отвязан от managed Nginx, а сервер получит сертификат для IPv4.
- **Let's Encrypt old.example → Let's Encrypt new.example** — оставьте режим
  Let's Encrypt и замените domain; сертификат выпускается для нового domain.
- Повторный Deploy с неизменными значениями остаётся допустимым.

Перед подтверждением Panel показывает Server IP, текущее и запрошенное
состояния. Subscription-файлы и локальные Registry entries при переходе не
удаляются, но URL прежнего domain больше не считается действующим. После смены
domain подписку нужно опубликовать повторно.

## Ошибки

Если Deploy не смог подтвердить домен или получить сертификат:

1. Проверьте A-запись и дождитесь завершения DNS-обновления.
2. Убедитесь, что домен указывает именно на выбранный Server IP.
3. Проверьте доступность портов 80 и 443.
4. Исправьте причину из итогового сообщения и повторите Deploy Nginx.

При ошибке прежняя рабочая конфигурация сохраняется. Автоматического перехода
на self-signed из-за ошибки выпуска или продления нет.

Доверенный TLS необходим для штатной публикации
[Subscriptions](<07 — Subscriptions.md>). Wildcard-сертификаты и DNS challenge не
поддерживаются; один Nginx Component управляет одним доменом.
