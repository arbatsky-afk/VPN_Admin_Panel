# SSH Fix

**SSH Fix** восстанавливает административный доступ по ключу после
переустановки VPS. Не запускайте его, если **Check SSH** уже завершается
успешно.

## Перед началом

Подготовьте:

- IPv4 сервера;
- выданный провайдером пароль пользователя `root`;
- доверенный SSH host-key fingerprint сервера из панели провайдера либо его
  web/VNC/serial-консоли;
- возможность парольного SSH-входа на сервер;
- административные ключи, настроенные через **Settings** панели;
- соответствующий `.pub`-файл рядом с каждым закрытым ключом;
- доступные в Windows команды `ssh` и `ssh-keygen`.

В **Settings** проверьте SSH port, список ключей и отметьте один ключ как
основной. Вручную редактировать локальные настройки не требуется.

SSH port должен совпадать с портом, на котором сервер принимает подключения
сейчас. После переустановки VPS провайдер может вернуть SSH на стандартный порт
`22`: в таком случае перед SSH Fix выберите в **Settings** порт `22`, даже если
раньше сервер использовал другой. SSH Fix не перебирает порты автоматически и
не меняет порт `sshd` на сервере.

Если сервер разрешает только вход по ключу, используйте консоль провайдера или
его механизм добавления SSH-ключа: SSH Fix не сможет войти по паролю.

Fingerprint должен описывать host key сервера, а не ваш локальный
административный ключ. Если провайдер не показывает fingerprints, выполните в
его доверенной консоли:

```bash
for key in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$key" -E sha256; done
```

Не получайте эталонный fingerprint через обычное SSH-подключение или локальный
`ssh-keyscan`: они используют тот же сетевой путь, который требуется проверить.

## Восстановление через Panel

1. Введите IPv4 сервера.
2. Включите **Editing**.
3. На вкладке **Deploy** нажмите **SSH Fix** и подтвердите операцию.
4. Проверьте показанную в окне PowerShell конечную точку `IPv4:port`, затем
   сравните алгоритм и `SHA256:...` fingerprint, показанные OpenSSH, с
   доверенными данными провайдера.
5. Только при точном совпадении введите `yes`. При отличии введите `no`, не
   вводите пароль и проверьте сервер через консоль провайдера.
6. После принятия проверенного host key введите root-пароль по запросу SSH.
7. Не закрывайте окно до завершения сценария.
8. Дождитесь автоматической проверки **Check SSH** в Panel.

Интерактивный вывод показывается в окне PowerShell, а итоговая проверка — в
Panel. После успешного завершения используйте административный ключ для
последующих операций.

## Ручной запуск

Из корня проекта можно открыть тот же штатный сценарий вручную:

```powershell
.\scripts\windows\restore-ssh.ps1 203.0.113.10
```

После его завершения выполните **Check SSH** в Panel.

## Безопасность

- Не закрывайте консоль провайдера, пока вход по ключу не подтверждён.
- Не принимайте новый host key без точного сравнения fingerprint с независимым
  доверенным источником. SSH Fix не принимает ключ автоматически.
- После успеха парольный SSH-вход отключается.
- Закрытые ключи не передаются на сервер; добавляются только публичные части.
- Не запускайте SSH Fix на работающем сервере без необходимости.
