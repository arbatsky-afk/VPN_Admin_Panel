# Запуск VPN Admin Panel

VPN Admin Panel — локальное Windows-приложение. Браузер и отдельный локальный
сервер для запуска не требуются.

## Первый запуск

1. Установите Python 3.13. Проект поддерживает версии `>=3.13,<3.14`.

2. Если Python-окружение ещё не подготовлено, выполните из корня проекта:

   ```powershell
   py -3.13 -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

3. Дважды щёлкните `run-admin-panel.vbs` в корне проекта.

При первом запуске отдельный deployment-конфиг создавать не нужно. SSH keys и
порт задаются через **Settings**; неизменяемые параметры первого Deploy панель
берёт из собственного tracked-ресурса.

При первом запуске Panel показывает главное окно. Чтобы при следующих запусках
оставлять его скрытым в системном трее, откройте **Settings**, в верхней строке
установите **Start minimized to tray** и сохраните настройки. Изменение
применяется при следующем запуске.

Admin Panel и Monitor хранят этот checkbox независимо. Если настройка
отсутствует или снята, соответствующее приложение показывает главное окно; если
она установлена, приложение запускается скрытым и открывается двойным щелчком
по своей иконке в трее либо пунктом **Open Admin Panel** / **Open Monitoring**
в её контекстном меню. При недоступном системном трее окно показывается
независимо от настройки. Кнопка `X` по-прежнему скрывает окно в трей; для
завершения приложения используется **Exit** в меню трея.

## Автозапуск Panel и Monitor

Для установки или обновления общего автозапуска выполните из корня проекта:

```powershell
& .\scripts\windows\manage-desktop-autostart.ps1 Install
```

Проверка состояния:

```powershell
& .\scripts\windows\manage-desktop-autostart.ps1 Status
```

Удаление автозапуска:

```powershell
& .\scripts\windows\manage-desktop-autostart.ps1 Remove
```

Panel и Monitor запускаются после входа текущего Windows-пользователя. После
ручного **Exit** или аварийного завершения они не перезапускаются автоматически
до следующего входа. После переноса каталога проекта повторно выполните
`Install`.

## Read only и Editing

Каждый запуск начинается в режиме **Read only**. Тумблер **Edit mode** справа в
строке вкладок выключен; включите его для редактирования и выключите, чтобы
вручную вернуться в Read only. Если Editing не выключен вручную, Panel
автоматически вернётся в Read only через 10 минут.

Глобальные действия **Settings**, **Check SSH** и **Reboot** находятся в строке
Server IP и Alias. Каждое действие состоит из подписи и компактной иконки;
назначение также отображается во всплывающей подсказке и доступно с клавиатуры.

В Read only доступны просмотр данных, **Check SSH**, обновление статусов,
управление состоянием служб, локальные Settings, **Save links** и создание
Backup. Editing требуется для Deploy, SSH Fix, добавления и удаления
пользователей, изменения конфигурации, Restore и удаления архивов.

Автоматический возврат в Read only не прерывает уже запущенную операцию. Режим
защищает от случайных изменений, но не является авторизацией и не заменяет
подтверждения опасных действий.

## Перезагрузка сервера

Действие **Reboot** в строке Server IP перезагружает выбранный сервер через SSH:

1. Проверьте выбранные Server IP и Alias и выполните **Check SSH**.
2. Включите **Editing** — в Read only кнопка Reboot недоступна.
3. Нажмите **Reboot** и ещё раз проверьте сервер в диалоге подтверждения.
4. Подтвердите операцию. Активные VPN-подключения будут прерваны.
5. После сообщения `Server reboot: scheduled` дождитесь запуска VPS и повторите
   **Check SSH**.

Результат `scheduled` подтверждает только планирование перезагрузки. Он не
означает, что сервер уже вернулся online. Не запускайте Reboot повторно только
из-за временной недоступности SSH.

Чтобы видеть вывод Python в терминале, запустите из корня проекта:

```powershell

```
