# Модульный деплой

На вкладке **Deploy** каждый Component устанавливается отдельной кнопкой. Это
позволяет подготовить новый сервер поэтапно и повторно запускать только нужную
установку.

## Подготовка сервера

1. Выберите сервер и выполните **Check SSH**.
2. Если доступ по административному ключу отсутствует после переустановки VPS,
   сначала используйте [SSH Fix](<02 — SSH-доступ.md>).
3. Включите **Editing**.
4. Установите **Base + Security** — это обязательная основа для остальных
   Components.

## Установка Components

После успешного **Base + Security** устанавливайте необходимые Components:

- **Xray**, **Hysteria2** и **Mieru** — VPN-службы, пользователи которых затем
  доступны на вкладке **Users**;
- **Docker** — среда для контейнерных служб;
- **Nginx** — управляемый HTTP/HTTPS endpoint;
- **Netdata** — мониторинг, доступный через Nginx.

Большинство Components можно устанавливать в любом порядке. **Netdata** требует
предварительно установленный Nginx; зависимость показана стрелкой между
кнопками.

Перед **Netdata** откройте **Settings → Netdata** и заполните **Claim token**.
Значение Claim token показывается открытым текстом. Поле **Claim rooms** можно
оставить пустым. Если обязательные данные не заданы, Panel остановит Deploy до
подключения к серверу.

При **Deploy Nginx** Panel сначала считывает актуальное состояние выбранного
сервера. Диалог сразу показывает действующий режим TLS и domain либо
Self-signed для первой установки. Выбранные Self-signed или Let's Encrypt с
lowercase domain становятся конечным состоянием Nginx; так же выполняются
отвязка domain и его прямая смена. Подготовка DNS описана в
[Доверенном TLS для Nginx](<05 — Доверенный TLS для Nginx.md>).

Параметры первой установки Xray, Hysteria2 и Mieru принадлежат приложению и не
требуют пользовательского JSON. Фактические Port, Protocol и SNI после
установки находятся только на сервере и показываются через Inventory/Management.

Кнопка **Amnezia** не устанавливает Component через Panel. Она показывает
информацию о подготовке внешнего приложения; подробности находятся в документе
[Установка AmneziaWG и подготовка клиентских конфигураций](<10 — Установка AmneziaWG и подготовка клиентских конфигураций.md>).

## Повторный Deploy

Установленный Component можно разворачивать повторно для обновления его
управляемой части. Подтверждённые VPN-порты и существующие пользовательские
доступы сохраняются из server-side recovery; локальный кэш параметров сервера
не используется.

Перед повторным Deploy:

1. Создайте актуальный [Backup](<08 — Backup и Restore.md>).
2. Проверьте Server IP и выбранный Component.
3. Прочитайте текст подтверждения.
4. Не закрывайте Panel до итогового результата.

Старая установка Netdata из Ubuntu repository с Basic Auth автоматически не
мигрирует. Перед первым Deploy текущей Netdata прежнюю установку необходимо
удалить отдельно.

## Результат и ошибки

- Успешный Deploy заканчивается итоговым сообщением в **Operation log**.
- Если обязательная зависимость отсутствует, Panel остановит установку и
  укажет, какой Component нужно установить первым.
- При ошибке не запускайте зависимые Components, пока причина не устранена и
  повторный Deploy не завершился успешно.
- Не запускайте параллельно другую серверную операцию и не закрывайте Panel во
  время Deploy.

AmneziaWG пока не входит в поддерживаемый модульный Deploy.
