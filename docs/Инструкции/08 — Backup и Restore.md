# Backup и Restore

Вкладка **Backup & Restore** создаёт локальные архивы выбранного сервера,
восстанавливает их и удаляет ненужные копии. Архивы содержат конфигурации и
секреты — храните их как конфиденциальные данные.

При открытии вкладки Panel только перечитывает локальный каталог архивов и не
проверяет сервер. Полный Inventory выбранного сервера запускается после команды
**Create backup** или **Restore selected backup**, когда он нужен для безопасного
плана операции.

## Создание Backup

Справа от таблицы расположена компактная вертикальная пара действий: сверху
обычная иконка **Create backup**, под ней предупреждающая иконка
**Restore selected backup**. Их названия показываются в tooltip и доступны
средствам accessibility.

1. Выберите сервер и откройте **Backup & Restore**.
2. Нажмите **Create backup**. Для этой операции режим **Edit mode** не
   требуется.
3. Дождитесь сообщения об успешном завершении и появления нового архива в
   таблице.

Панель создаёт только полный согласованный Backup установленных Components.
Если необходимые данные недоступны или состояние сервера не позволяет собрать
полный архив, операция завершается ошибкой и частичный архив не сохраняется.

## Список и удаление архивов

- Свежие архивы находятся сверху.
- Фильтр **Source IP** показывает архивы одного исходного сервера.
- Кнопка обновления перечитывает локальный каталог архивов.
- Для удаления включите **Edit mode** и нажмите корзину
  **Delete Backup archive** в колонке **Actions** нужной строки. Выбирать строку
  перед удалением не требуется. Подтвердите удаление указанного архива
  в открывшемся диалоге. После подтверждения удаление не может быть отменено
  средствами Panel.

## Restore

Перед восстановлением установите на целевом сервере **Base + Security** и те же
Components, данные которых находятся в архиве. Исключение — межсерверный
Restore, при котором Nginx намеренно не восстанавливается и не обязан быть
установлен на цели. Restore возвращает настройки и данные, но не устанавливает
отсутствующие программы или Components.

1. Выберите целевой сервер.
2. В таблице выберите нужный архив; при необходимости используйте фильтр
   **Source IP**.
3. Включите **Edit mode** и нажмите **Restore selected backup**.
4. Дождитесь проверки архива и совместимости целевого сервера.
5. Если исходный и целевой IP различаются и архив содержит Nginx, проверьте
   отдельное предупреждение: Nginx будет пропущен, а списки применяемых и
   пропускаемых Components указаны явно. Для архива без Nginx остаётся обычное
   подтверждение межсерверного переноса.
6. Проверьте итоговое подтверждение: архив, исходный и целевой серверы,
   применяемые и пропускаемые Components, количество перезаписываемых путей и
   реальные действия над службами.
7. Нажмите **Restore** и дождитесь итоговой проверки состояния Components.

Если архив повреждён, имеет неподдерживаемый формат или несовместим с целевым
сервером, Panel остановит операцию до применения данных.

При совпадающих IPv4 Nginx восстанавливается штатно. При разных IPv4 Panel
полностью исключает Component Nginx: конфигурация, TLS-сертификат и ключ,
домен, опубликованные subscriptions, firewall-фрагмент и перезапуск Nginx на
целевом сервере остаются без изменений. Исключение выполняется по Component,
поэтому принадлежащая Netdata reverse-proxy конфигурация продолжает
восстанавливаться вместе с Netdata. Архив, включая Nginx, всё равно полностью
проверяется до запуска; архив только с Nginx блокируется, потому что применять
нечего.

Успешный межсерверный Restore с исключённым Nginx завершается предупреждением
`Restore completed with policy exclusions. Skipped: nginx.` Это ожидаемый
успех с исключением, а не аварийный частичный результат. Статус существующего
Nginx цели может быть показан отдельно как сохранённый, но не восстановленный.

## Безопасность и ошибки

- Перед Restore создайте свежий Backup текущего состояния целевого сервера.
- Первая проверка нового набора Components должна выполняться на тестовом
  сервере.
- Ошибка после начала Restore может оставить часть данных уже изменённой;
  автоматического отката нет.
- Не прикладывайте архив к тикетам и не отправляйте его незашифрованным через
  почту или мессенджеры.
