# Subscriptions

Вкладка **Subscriptions** объединяет выбранные VPN-ссылки одного пользователя
и публикует их по единому HTTPS URL.

## Перед началом

1. Проверьте **Server IP** и выполните **Check SSH**.
2. Убедитесь, что на сервере настроен доверенный TLS. При необходимости
   используйте инструкцию
   [Доверенный TLS для Nginx](<05 — Доверенный TLS для Nginx.md>).
3. На вкладке **Users** сохраните connection-файлы нужного пользователя через
   **Save links**. Работа с пользователями описана в документе
   [Управление пользователями](<06 — Управление пользователями.md>).

## Создание или обновление подписки

1. Выберите сервер публикации в поле **Server IP**.
2. Откройте вкладку **Subscriptions**.
3. Выберите пользователя в поле **Name**.
4. Проверьте список connection-файлов. Изначально отмечены все файлы выбранного
   пользователя; ненужные можно снять вручную. Checkbox в заголовке таблицы
   отмечает или снимает весь список.
5. Включите **Edit mode** и нажмите иконку **Publish selected** справа от
   поля **Name**.
6. Проверьте Server IP, Name и количество файлов в окне подтверждения, затем
   разрешите публикацию.

**Server IP** определяет сервер, на котором будет опубликована подписка. Он не
фильтрует список connection-файлов: в таблице могут находиться сохранённые
ссылки этого пользователя с разных VPN-серверов.

Компактные поле **Name** и иконка **Publish selected** образуют одну группу у
левого края таблицы connection-файлов. Иконка использует символ загрузки;
название действия показывается в tooltip и доступно средствам accessibility.
Действие недоступно, если
пользователь не выбран, не отмечен ни один файл, выключен **Edit mode** или уже
выполняется другая серверная операция.

## Опубликованные подписки на выбранном сервере

При открытии вкладки Panel выполняет целевую Inventory-проверку регистрации и
декларации Nginx для выбранного **Server IP**, не проверяя runtime-состояние
остальных Components. Если на сервере зарегистрирован совместимый managed Nginx
contract v5 в режиме Let's Encrypt, таблица **Published on &lt;Server IP&gt;** справа
показывает опубликованные имена и их состояние. Кнопка **Refresh** рядом с
заголовком повторяет безопасную read-only проверку и доступна без Edit mode.
Доступные действия удаления находятся в колонке **Actions** соответствующей
строки.

Серверный блок прижат к правому краю и отделён от локального выбора слева.
Первая строка показывает результат проверки, например
**Ready · vpn.example.com**. Ниже заголовок **Published on 203.0.113.10** явно
указывает выбранный в верхней части окна Server IP. При переключении сервера IP
и содержимое таблицы обновляются для одной серверной пары. Во время проверки и
при ошибке первая строка показывает соответствующее состояние:

- **Checking managed Nginx…**;
- **Loading published subscriptions…**;
- **Unavailable · Managed Nginx is not installed.**;
- **Error · Inspection failed: …**.

Основные состояния:

- **Active** — Registry и сервер содержат одну точную идентичность;
- **Missing** — желаемая запись есть в Registry, но соответствующего файла на
  сервере нет;
- **Orphan** — допустимый серверный файл не соответствует записи Registry;
- **Active + orphan** — точный файл есть вместе с лишним файлом того же Name;
- **Missing + orphan** — желаемого файла нет, но есть файл того же Name с
  другим token;
- **Deleting** — ранее начатое полное удаление ещё требует завершения или
  повторной проверки;
- **Republish required** — точный файл и Registry token сохранились, но
  подтверждённый в Registry domain отличается от текущего domain Nginx.

Registry задаёт желаемые подписки. Поэтому **Missing** не приводит к
автоматической публикации, удалению записи или замене token: он сохраняется для
будущей публикации той же пары **Server IP + Name**.

### Delete orphan

В строке с orphan-состоянием включите **Edit mode** и нажмите компактное
действие **Delete orphan** в колонке **Actions**. После подтверждения Panel
удалит только лишние серверные файлы выбранного Name. Registry не изменяется;
при наличии точного Active-файла он сохраняется.

### Delete active

Для состояния **Active**, **Active + orphan**, **Republish required** или
незавершённого **Deleting** можно нажать компактное действие **Delete active**
в колонке **Actions** соответствующей строки. После подтверждения Panel удаляет
все принадлежащие панели серверные файлы выбранного Name и соответствующую
запись Registry. Для **Missing** эта операция недоступна.

Если результат удаления `partial` или `unknown`, Panel сохраняет намерение
`Deleting` и повторно считывает состояние сервера. Не считайте удаление
завершённым, пока новая проверка не подтвердит отсутствие файлов.

Сторонний Nginx, несовместимый contract и self-signed режим не дают доступа к
списку и удалению. Открытие вкладки и Refresh никогда не удаляют orphan-файлы
автоматически.

## Subscription URL

После успешной публикации ссылка появляется в поле **Subscription URL** и
автоматически копируется в clipboard. Кнопка справа от поля копирует её
повторно.

Повторная публикация для той же пары **Server IP + Name** сохраняет bearer token
и обновляет содержимое. Пока domain Nginx не изменился, URL остаётся прежним.
После смены domain состояние становится **Republish required**; повторная
публикация подтверждает новый host, и URL меняется только в части domain.

Subscription URL предоставляет доступ без дополнительного ввода пароля.
Передавайте и храните его как секрет.

После открытия вкладки и завершения проверки Panel выделяет первую строку
таблицы **Published on &lt;Server IP&gt;**. Поле **Subscription URL** относится к
выделенной строке и обновляется при выборе другой строки. Подтверждённый URL
показывается только для состояний **Active** и **Active + orphan**; для остальных
состояний поле очищается. Выбор строки справа не изменяет поле **Name** и список
локальных connection-файлов слева. В self-signed режиме и при несовпадении
domain URL не показывается. При уходе с вкладки Name, список файлов и URL
очищаются.

## Если операция не завершилась успешно

- **published, but cleanup is incomplete** — новое содержимое опубликовано и
  показанный URL можно использовать, но очистка прежних данных не завершена.
  Повторите публикацию; если предупреждение сохраняется, проверьте состояние
  сервера.
- **failed** — публикация не подтверждена. Исправьте причину из итогового
  сообщения и повторите операцию.
- **result unknown** — Panel не может достоверно определить результат. Не
  считайте содержимое обновлённым; проверьте доступность сервера и повторите
  публикацию для той же пары Server IP + Name.

После неудачной или неизвестной повторной публикации прежний URL снова
показывается, если Refresh подтверждает точный файл на сервере и прежний domain.
Это подтверждает доступность URL, но не успешное обновление его содержимого.

Если нужный Name или connection-файлы не появились, вернитесь на **Users**,
повторно выполните **Save links**, затем заново откройте **Subscriptions**.
