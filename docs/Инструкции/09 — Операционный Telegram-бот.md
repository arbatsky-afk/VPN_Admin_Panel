# Операционный Telegram-бот

Операционный Telegram-бот позволяет проверять серверы и выполнять ограниченный
набор действий Admin Panel удалённо. Бот работает только пока запущена Admin
Panel, в том числе когда её окно скрыто в системном трее.

## Возможности и ограничения

Через Telegram доступны:

- получение актуального Inventory сервера;
- **Start**, **Stop** и **Restart** поддерживаемых служб;
- **Reboot** сервера после отдельного подтверждения.

Список серверов берётся из сохранённого списка Admin Panel. Сначала добавьте
сервер в Panel и убедитесь, что он доступен в выпадающем списке Server IP.

Через Telegram недоступны Deploy, SSH Fix, Enable/Disable служб, Users,
Subscriptions, Backup/Restore, изменение Port/SNI, SSH keys и произвольные
серверные команды. Бот не показывает VPN-ссылки, credentials и содержимое
конфигов.

## Создание бота и получение Chat ID

1. Откройте официального **@BotFather**, выполните `/newbot` и сохраните выданный
   Bot token. Актуальная процедура приведена в
   [официальной инструкции Telegram](https://core.telegram.org/bots/features#botfather).
2. Откройте личный чат с новым ботом либо добавьте его в нужную группу и
   отправьте сообщение или команду.
3. До включения бота в Admin Panel получите числовой Chat ID через официальный
   метод Bot API
   [getUpdates](https://core.telegram.org/bots/api#getupdates). Чтобы токен не
   попал в историю команд PowerShell, введите его через отдельный prompt:

   ```powershell
   $telegramBotToken = Read-Host "Bot token"
   $response = Invoke-RestMethod -Uri "https://api.telegram.org/bot$telegramBotToken/getUpdates"
   $response.result |
       ForEach-Object { $_.message.chat } |
       Where-Object { $_ } |
       Select-Object id, type, title, username
   Remove-Variable telegramBotToken
   ```

4. Выберите `id` нужного чата. У группового чата значение может быть
   отрицательным. Если список пуст, отправьте боту новое сообщение и повторите
   запрос.

Bot token предоставляет управление ботом. Не публикуйте его, не вставляйте в
URL браузера и не пересылайте другим пользователям. В Settings значение
показывается открытым текстом.

## Настройка и привязка пользователя

Настройка доступна в Read only и не требует **Editing**:

1. Откройте **Settings → Telegram Bot**.
2. Заполните **Bot token** и **Chat ID**. Эти поля должны быть заполнены вместе.
3. При необходимости измените **Audit log retention (days)**. Допустимы значения
   от 1 до 3650, по умолчанию используется 30 дней.
4. Нажмите **Save**. В нижней строке Panel появится состояние
   `Telegram: Pairing required`.
5. Снова откройте **Settings → Telegram Bot** и нажмите **Detect User ID**.
6. Отправьте показанную команду `/identify <код>` в настроенный Telegram-чат в
   течение пяти минут. Используйте команду целиком и не передавайте код другим.
7. После сообщения `User detected` нажмите **Save**, чтобы сохранить Authorized
   User ID.
8. Убедитесь, что нижняя строка показывает `Telegram: Online`.

После смены Bot token или Chat ID сохранённый Authorized User ID сбрасывается и
привязку необходимо пройти заново. Пять неверных попыток `/identify` отменяют
текущий код; в этом случае нажмите **Detect User ID** ещё раз.

Чтобы отключить бота, очистите одновременно Bot token и Chat ID и сохраните
Settings.

## Работа с ботом

Отправьте `/start` для открытия меню или `/menu` для возврата в его корень:

1. Откройте **Servers** и выберите сервер.
2. Откройте **Services**. Бот соберёт актуальный Inventory и после завершения
   покажет доступные Components и службы.
3. Выберите Component или службу и доступное действие **Start**,
   **Stop** либо **Restart**.
4. Для перезагрузки вернитесь в меню сервера, выберите **Reboot** и нажмите
   одноразовое **Confirm reboot**.

Start, Stop и Restart запускаются без дополнительного подтверждения и могут
прервать активные подключения. Reboot всегда требует подтверждения. Режим
Editing в окне Panel на Telegram-действия не распространяется: доступ
ограничивается привязанными Chat ID и Authorized User ID.

Перед Start и Restart Panel проверяет конфигурацию Component. Stop не
блокируется повреждённой конфигурацией, чтобы службу можно было выключить; если
после этого полный итоговый статус недоступен, бот покажет `unknown` и выполнит
повторную проверку.

GUI и Telegram выполняют не более одной общей серверной операции одновременно.
Если Panel занята, команда Telegram отклоняется и не ставится в очередь.

## Статус и ошибки

Состояние бота отображается в нижней строке Admin Panel:

- `Disabled` — настройки отсутствуют или невалидны;
- `Starting` — бот подключается к Telegram;
- `Pairing required` — требуется привязать Authorized User ID;
- `Online` — бот готов принимать команды;
- `Offline / reconnecting` — Telegram API временно недоступен, выполняется
  переподключение.

При восстановлении связи команды и операции не повторяются автоматически. Если
серверное действие завершилось с `unknown`, дождитесь показанной ботом повторной
проверки и проверьте сервер перед следующим действием.

Кнопка `X` скрывает Admin Panel в системный трей и оставляет бота работающим.
Пункт **Exit** в меню трея завершает и Panel, и Telegram-бота.
