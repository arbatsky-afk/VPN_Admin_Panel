# Сборка дерева прокси для mihomo

Генератор объединяет прокси из YAML-файлов и создаёт готовое дерево
`proxies` и `proxy-groups` для mihomo. Параметры `dns`, `tun`, порты, `rules`
и `rule-providers` остаются в базовом конфиге и подключаются к дереву через
Merge.

## Перед началом

- В корне проекта должно быть подготовлено `.venv` с зависимостями проекта.
- Исходные файлы должны быть корректным YAML в UTF-8.
- Каждый прокси должен содержать непустой `type`, а его `server` — IP-адрес.

Генератор обрабатывает все файлы `*.yaml` и `*.yml` из `tools\in\`. Не
оставляйте в этом каталоге посторонние YAML-файлы: происхождение прокси и имя
исходного файла при сборке не учитываются.

Поддерживаются три формы входного документа:

- mapping с ключом `proxies`, содержащим список прокси;
- список прокси;
- mapping одного прокси без ключа `proxies`.

Файл `proxy-tree.yaml` зарезервирован для результата и как источник не
обрабатывается.

## Сборка

1. Поместите исходные YAML-файлы в `tools\in\`.
2. Запустите `tools\proxytree.cmd` двойным кликом.
3. Дождитесь сообщения о результате и нажмите любую клавишу, чтобы закрыть
   окно.
4. Подключите `tools\in\proxy-tree.yaml` к базовому конфигу mihomo через
   Merge.

Если исходных прокси нет, это штатный результат: генератор ничего не записывает,
а существующий `proxy-tree.yaml` оставляет без изменений.

## Результат

Генератор создаёт трёхуровневое дерево:

```text
Bypass
├── 192.0.2.10
│   ├── 192.0.2.10-trojan
│   └── 192.0.2.10-vless
└── 198.51.100.20
    ├── 198.51.100.20-hysteria2
    └── 198.51.100.20-vless
```

- `Bypass` — корневая группа типа `select`; правила базового конфига должны
  ссылаться на это имя.
- Для каждого IP создаётся отдельная серверная группа.
- Прокси получают имена из IP, типа протокола и, при необходимости, числового
  суффикса.
- Полностью одинаковые по параметрам прокси объединяются, даже если в исходных
  файлах у них разные имена.

Файл содержит только дерево прокси. Группа `DIRECT` в корень не добавляется.

## Выбор типа серверной группы

Для каждой серверной группы результат содержит три варианта `type`, из которых
активен один:

```yaml
- name: "192.0.2.10"
  # type: fallback
  type: url-test
  # type: select
```

Чтобы изменить поведение группы, закомментируйте текущую строку `type` и
раскомментируйте одну из строк `fallback`, `url-test` или `select`. При следующей
сборке генератор прочитает действующий `proxy-tree.yaml` и сохранит выбранный
тип для существующей группы. Новые группы получают тип `url-test`.

Остальные ручные изменения результата при следующей сборке не сохраняются.

## Ошибки входных файлов

При некорректном YAML, неподдерживаемой форме документа, отсутствии `server`
или `type`, либо значении `server`, которое не является IP-адресом, генератор
выводит имя проблемного файла и не создаёт новый результат. Окно остаётся
открытым, чтобы сообщение можно было прочитать.

YAML, полученный преобразователем AmneziaWG, можно использовать как обычный
источник. Само преобразование описано в
[инструкции по подготовке клиентских конфигураций](<10 — Установка AmneziaWG и подготовка клиентских конфигураций.md#преобразование-клиентского-конфига-в-yaml>).
